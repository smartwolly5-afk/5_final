# 05. 함수 목록

파일별 함수 표입니다(파일 순서 = 중요도 순). **위치·입력·호출 위치는 실제 코드에서 자동으로 뽑았습니다**
(`10_코드_라인별_설명/_생성기/gen_functions.py`, 코드가 바뀌면 다시 실행).

- **입력** = 함수 괄호 안 인자(argument, 함수에 넘기는 값). `x=None` 은 안 주면 None(값 없음)으로 시작한다는 뜻.
- **누가 호출하나** = 그 함수를 부르는 코드 위치(`파일:줄`). `HTTP GET /주소` 는 브라우저가 그 주소로 요청하면 실행된다는 뜻.
  6곳이 넘으면 `…` 으로 줄였습니다. "— (스크립트 실행·테스트)" 는 코드 안에서는 부르지 않고 명령줄 실행이나 테스트에서 쓰는 함수입니다.
- JavaScript 함수의 '하는 일'은 함수 첫 줄 주석입니다.

## 호출 관계도 — `analyze` 한 번에 무엇이 어떤 순서로 불리나

```mermaid
flowchart TB
    R["POST /api/analyze<br/>__init__.analyze"] --> PA["pipeline.analyze"]
    PA --> V2["_v2_detections<br/>→ track.aggregate · judge.judge"]
    PA --> TO["judge.threat_of · _target_tags<br/>(tactic_weights · _group_p75 → dictdb)"]
    PA --> AC["adapter.assess_cluster<br/>(to_assess_input → from_assess_output)"]
    AC --> AS["response_level.assess<br/>(판정 엔진 하나, 경계값 load_coef)"]
    R --> AT["_attach"]
    AT --> TC["media.track_crop"]
    AT --> RE["unknown_registry.record"]
    AT --> SV["response_level.save_assessment<br/>(cluster_assessment)"]
    P2["PATCH 전술·지휘전차·핵심표적<br/>POST 단계 조정"] --> LA["_log_action → response_level.record_override<br/>(commander_override)"]
```

순서: ① `pipeline.analyze` 가 `_v2_detections`(트랙 집계 → 판정)를 먼저 하고 ② 군집마다 전술 추정 → 표적마다 위협도·태그
③ 군집 판정은 `adapter.assess_cluster` → `response_level.assess` (엔진 하나) ④ 계산이 끝나면 라우트가 `_attach` 로 crop·레지스트리·판정 기록(`cluster_assessment`) 저장 ⑤ `_respond` 로 JSON 응답. 지휘관 조치 라우트는 재계산 후 `_log_action` 으로 `commander_override` 에 남깁니다.
