# 부록 — 용어집

한글 용어는 가나다순, 그다음 영문 용어는 알파벳순입니다.

| 용어 | 쉬운 설명 | 이 프로젝트에서의 의미 |
|---|---|---|
| 계열 (family) | 같은 원형에서 나온 전차 묶음 | 예: T-72, T-72A, T-72B3 → 'T-72 계열'. 사전 `family_name` 기준 |
| 구경장 | 포신 길이 ÷ 구경. 길수록 포탄이 빠름 | 화력 식에서 (구경장/44)^0.5 |
| 군집 (cluster) | 같이 움직이는 전차·차량 무리 | 대응단계를 정하는 단위. 입력의 `cluster_id` (현재 mock 은 C-1) |
| 군집점수 S | 군집 최고 위협도 × 제대가중치 | 225/150/75 경계로 1~4단계 |
| 근거 태그 | 판단 이유를 짧은 문장 칩으로 보여 준 것 | '안테나 탐지 5/5프레임 → 지휘전차 추정' 등 (`pipeline.py:107`) |
| 기동력 (M) | 얼마나 빨리 움직이나 | 출력대중량비 ÷ 26.22 (M1A1 = 1.0) |
| 기준전차 | 점수 100(비율 1.0)의 기준 | M1A1 Abrams (TANK_0120) |
| 대응단계 | 군집에 대한 대응 수준 1~4 | 1 즉시 보고, 2 우선 감시, 3 지속 감시, 4 관심 |
| 데코레이터 | 함수 위에 `@` 로 붙여 기능을 덧붙이는 표시 | `@bp.get("/주소")` = 그 주소 요청 때 함수 실행 |
| 레지스트리 | 계속 쌓아 두는 등록부 | 미확인 전차 그룹 DB (`unknown_registry.py`) |
| 방호력 (P) | 얼마나 잘 버티나 | 장갑계수 × 높이 보정 |
| 백분위수 / 상위 25% (p75) | 값을 줄 세웠을 때 75% 위치의 값 | 미확인·계열만 확정 전차에 주는 위협도 |
| 블루프린트 (Blueprint) | Flask 주소 묶음 | dashboard, dictionary, threat 3개 (`app.py:12~14`) |
| 사전 | 전차 369종 제원 데이터와 그 화면 | `tank_specs` 테이블, `/dictionary` |
| 세대 | 전차 기술 세대 (1·2·3·3.5세대) | 화력 식의 세대계수 (3세대 1.0) |
| 순위 점수 (priority) | 미확인 그룹을 줄 세우는 점수 | 위협도 × 빈도 × 영상 수 × 최근성 |
| 신뢰도 | ① 탐지 신뢰도: 모델이 얼마나 확신하나 (0~1) ② 데이터 신뢰도: 사전 값을 몇 개 대체했나 (상·중·하) | ①은 박스 라벨 '81%', ②는 `tank_threat.confidence` |
| 위협도 (T) | 전차 1대가 얼마나 위험한지 (M1A1 = 100) | 전술 가중 평균. 100↑ 매우 높음, 70↑ 높음, 40↑ 보통 |
| 유형 (type_group) | 주력전차·경전차 같은 큰 분류 | 계열 표본이 부족할 때 대체값 단위 |
| 임베딩 | 사진을 숫자 벡터로 바꾼 것. 비슷한 사진은 비슷한 방향 | DINO 출력. 샘플은 16개 숫자 |
| 전술 가중치 | 전술마다 화력·기동·방호 중요도 | 전문가 설문 10가지 (`config.py:26~37`) |
| 정규화 (L2) | 벡터 길이를 1로 맞추기 | 방향만 비교하려고 (`track.py:143~145`) |
| 제대 | 부대 규모 (소대·중대·대대) | 전차+기갑차 1·5·16대 이상 → 가중치 1·2·3 |
| 지휘전차 | 지휘관이 탄 전차 (안테나가 많음) | 안테나 30%·3프레임 이상 → ⑩지휘통제 가중치 |
| 추적 ID (tracking_id) | 영상 안에서 같은 개체에 계속 붙는 번호 | YOLO 쪽 트래커가 붙인다고 가정 |
| 출력대중량비 | 엔진 마력 ÷ 무게 (hp/t) | 기동력 계산 |
| 코사인 유사도 | 두 벡터 방향이 얼마나 비슷한지 (-1~1, 1에 가까울수록 비슷함) | ≥ 0.85 면 같은 미확인 그룹 |
| 탄종 | 포탄 종류 (APFSDS, HEAT …) | 화력 식의 탄종계수 (APFSDS 1.0) |
| 트랙 (track) | 한 개체가 여러 프레임에 걸쳐 나온 기록 | 판정·저장의 단위 (`track.py`) |
| 프레임 | 영상의 한 장면 사진 | 샘플은 영상당 5장 |
| 하위 호환 | 예전 형식 입력도 계속 받음 | v1 mock(`detections` 목록, % bbox) |
| 하한 규칙 | 단계가 너무 낮게 나오지 않게 막는 규칙 | 미확인·위협도 75↑ 전차 → 최소 3단계 |
| 화력 (F) | 얼마나 세게 쏘나 | 구경·구경장·탄종·세대 |
| API | 프로그램끼리 데이터를 주고받는 주소 | `/api/analyze` 등 (08번 문서) |
| bbox (바운딩 박스) | 표적을 둘러싼 네모 상자 | `bbox_px` 픽셀, `bbox` 화면 % |
| CDN | 인터넷으로 라이브러리 파일을 받아 오는 곳 | Leaflet, Pretendard |
| centroid | 그룹 임베딩들의 평균 (중심) | 새 미확인과 비교하는 기준 |
| cope cage | 포탑 위 철망 지붕. 드론·위에서 떨어지는 공격 대비 | 방호 ×1.10 (임시값) |
| crop | 사진에서 표적 부분만 잘라낸 것 | 상세 패널·미확인 갤러리 (`media.py`) |
| DB (데이터베이스) | 표를 저장하는 프로그램 | MySQL `tank`, 데모는 SQLite |
| DINO | 모델 팀의 기종 분류 모델 | top_k·임베딩 출력 (연결 전) |
| Flask | 파이썬 웹 서버 라이브러리 | `app.py` |
| IoA | 부품 넓이 중 전차 상자와 겹치는 비율 | ≥ 0.5 면 그 전차 부품 |
| JSON | `{"키": 값}` 형태의 데이터 글자 | API 요청·응답, mock 입력 |
| Known / Known_Variant / Unknown | 기종 확정 / 계열만 확정 / 모름 | 판정 결과 (`judge.py`) |
| Leaflet | 웹 지도 라이브러리 | 미니맵 |
| mock | 진짜 대신 흉내 낸 임시 데이터 | 모델 출력 대신 `static/mock_frames/*.json` |
| MPI | 화력·기동·방호를 하나로 합친 참고 점수 | 상세 패널 참고값 (위협도 계산에는 안 씀) |
| PK (기본 키) | 행을 하나로 특정하는 값 | `tank_id`, `group_id` |
| SQL 인젝션 | 입력에 DB 명령을 끼워 넣는 공격 | `%s` 자리표시자로 막음 |
| SQLite | 파일 하나짜리 DB | `TANKLAB_DEMO=1` 데모·테스트 |
