# 06. 계산식 정리

모든 공식을 **① 수식 → ② 말로 풀이 → ③ 샘플 숫자 대입** 순서로 씁니다. 숫자는 샘플(`static/mock_frames/`)을 실제로 실행한 값이고,
사전 DB 값은 MySQL `tank_threat` 테이블(= `dashboard/threat/demo_seed.json` 과 같은 값)입니다.

> 두 경로가 있습니다.

> - **v1 (예전 mock, 하위 호환)**: `tank_specs.json` 4종으로 직접 계산. 7절.

## 1. 화력·기동력·방호력 (사전 DB, 기준전차 M1A1 = 1.0)

계산 위치: `threat_calc.py:254~263` `py_threat` (사전 전체를 `sync_threat_db.py` 가 미리 계산해 `tank_threat` 에 저장)

**① 수식**
```
F (화력)   = (구경 / 120) × (구경장 / 44)^0.5 × 탄종계수 × 세대계수
M (기동력) = 출력대중량비 / 26.22
P (방호력) = 장갑계수 × clip( (2.44 / 차체높이)^0.5 , 0.85, 1.15 )
```
**② 풀이**: 기준전차 M1A1(120mm, 44구경장, 26.22hp/t, 높이 2.44m)과 비교한 비율입니다. 1.0 이면 M1A1 과 같음.
구경장은 제곱근을 씌워 영향을 줄이고, 탄종(APFSDS 1.0, 포발사 ATGM 0.8, HEAT 0.6 …)과 세대(3.5세대 1.1, 3세대 1.0, 2세대 0.75 …)를 곱합니다.
차체가 낮을수록 맞기 어려워 방호가 조금 오르되, 그 효과는 0.85~1.15 배로 제한(clip)합니다. 계수는 DB `threat_coef`, `ammo_coef`, `gen_coef` 테이블.

**③ 대입 — Tank-01 = TANK_0230 (T-90)**: 125mm, 48구경장, APFSDS, 3세대, 18.2hp/t, 장갑 0.8(복합장갑 3세대), 높이 2.23m
```
F = (125/120) × (48/44)^0.5 × 1.0 × 1.0 = 1.0417 × 1.0445 = 1.0880
M = 18.2 / 26.22 = 0.6941
P = 0.8 × (2.44/2.23)^0.5 = 0.8 × 1.0460 = 0.8368
```
**Tank-11 = TANK_0222 (T-80)**: 125mm, 48, APFSDS, **2세대(0.75)**, 23.8hp/t, 장갑 0.7, 높이 2.19m → F = 0.8160, M = 0.9077, P = 0.7389

## 2. 전술 가중치와 전차 1대 위협도 T

계산 위치: v2 Known `dashboard/threat/judge.py:88~92`, 사전 전체 `threat_calc.py:261~262`, 가중치 `dashboard/threat/config.py:26~37`

**① 수식**
```
T_k = 100 × (w_F·F + w_M·M + w_P·P) / (w_F + w_M + w_P)      (k = 전술 번호 1~10)
```
**② 풀이**: 전술에 따라 화력·기동·방호 중 무엇이 중요한지 다르므로 가중 평균합니다. 가중치 합으로 나눠서 합이 0.99 인 전술도 M1A1 = 100 이 유지됩니다.
지휘전차는 군집 전술과 상관없이 ⑩지휘통제 가중치(`core.py:85`). 군집에 지휘전차가 있으면 군집 전술도 ⑩으로 자동 추정(`core.py:61`).

**전술 가중치 표** (출처: `위협도_컬럼_산출.xlsx` '전술가중치' 시트 = 전문가 설문, `config.py:23` 주석)

| 번호 | 전술 | w_F (화력) | w_M (기동) | w_P (방호) | 합 |
|---|---|---|---|---|---|
| 1 | 기동·직접전투 (지휘전차 없을 때 기본) | 0.45 | 0.35 | 0.20 | 1.00 |
| 2 | 병력수송·지원 | 0.21 | 0.43 | 0.36 | 1.00 |
| 3 | 대전차 | 0.38 | 0.28 | 0.34 | 1.00 |
| 4 | 간접화력 | 0.61 | 0.22 | 0.17 | 1.00 |
| 5 | 장거리화력 | 0.72 | 0.15 | 0.12 | 0.99 |
| 6 | 방공 | 0.54 | 0.21 | 0.25 | 1.00 |
| 7 | 정찰·표적획득 | 0.19 | 0.51 | 0.30 | 1.00 |
| 8 | 공병 | 0.17 | 0.44 | 0.39 | 1.00 |
| 9 | CBRN·연막차폐 | 0.18 | 0.36 | 0.46 | 1.00 |
| 10 | 지휘통제 (지휘전차) | 0.19 | 0.43 | 0.37 | 0.99 |
| 11 | 전투근무지원 | 화력 0 → 전차에 쓰지 않음 | | | |

**③ 대입**
```
Tank-01 (T-90, 지휘전차 → 전술 10):
  T = 100 × (0.19×1.0880 + 0.43×0.6941 + 0.37×0.8368) / 0.99
    = 100 × (0.2067 + 0.2985 + 0.3096) / 0.99 = 100 × 0.8148 / 0.99 = 82.3

Tank-11 (T-80, 지휘전차 아님 → 전술 1):
  T = 100 × (0.45×0.8160 + 0.35×0.9077 + 0.20×0.7389) / 1.00 = 36.72 + 31.77 + 14.78 = 83.3
```

**참고 — 사전 화면의 정량 위협도** (`dictionary.py:279` `quant_threat`): 전술 가중치 없이 `100 × (F + M + P) / 3`.
T-90 → 100 × (1.0880 + 0.6941 + 0.8368)/3 = 87.3. 대시보드(전술 반영)와 사전(정량만)은 **일부러 다르게** 계산합니다.

## 4. 제대·군집점수·대응단계·하한 규칙 (판정 엔진 `response_level.assess` 하나)

계산 위치: `response_level.py:98~104` (대수·제대), `response_level.py:106~122` (점수·단계·하한), 제대 표 `response_level.py:28`,
경계값 `response_level.py:145` `load_coef` (DB `threat_coef` → 없으면 `config.py:46~48`), 대시보드 변환 `adapter.py:26`

**① 수식**
```
대수 N   = 군집 안 '전차' + '기갑차' + 미확인(포병·인원 분류는 제외) 수        ← 엔진 통합 후 미확인 포함 (규칙 ④)
           v2 입력은 프레임마다 동시에 보인 대수의 최댓값 (같은 차량을 여러 번 세지 않음)
           스위치 config.ECHELON_COUNT_UNKNOWN = False 면 예전처럼 전차 + 기갑차만
제대     = N ≥ 16 → 대대(E=3) / N ≥ 5 → 중대(E=2) / N ≥ 1 → 소대(E=1) / 0 → 없음(E=0)
T_cluster = 군집 안 표적 위협도의 최댓값 (대시보드가 계산한 T: cope cage·계열 p75·지휘전차 반영)
S        = T_cluster × E
단계     = S ≥ lv1(225) → 1(즉시 보고) / S ≥ lv2(150) → 2(우선 감시) / S ≥ lv3(75) → 3(지속 감시) / 그 밖 → 4(관심)
하한     = 항상 적용 (가장 높은 단계를 고름):
           미확인 포함(포병 제외) → 최소 3단계
           위협도 ≥ floor_t(75) 인 확인 전차(미확인 아님) 포함 → 최소 3단계
           핵심표적 지정(지휘관) → 최소 2단계
```
**② 풀이**: 평균이 아니라 **가장 위험한 1대** 기준이고, 무리가 클수록(중대·대대) 배로 키웁니다. 미확인이 섞이거나 강한 전차가 있으면 '관심'까지 내려가지 않게 막고,
지휘관이 꼭 대응할 표적을 지정하면 최소 '우선 감시'로 올립니다.

**③ 대입**
```
영상 A, 군집 C-1: 5프레임 모두 Tank-01, Tank-02, UNK-001(미확인) → N = 3 → 소대, E = 1
  T_cluster = max(88.9, 88.7, 82.3) = 88.9 → S = 88.9 × 1 = 88.9 → 75 이상 → 3단계 지속 감시
  Tank-01 을 핵심표적으로 지정하면 → 하한 '핵심표적 지정 → 최소 2단계' → 2단계 우선 감시 (조치 전 3단계)
영상 B, 군집 C-1: Tank-11 + UNK-007(미확인) → N = 2 → 소대, E = 1
  T_cluster = max(99.5, 83.3) = 99.5 → S = 99.5 → 3단계 지속 감시
```
> 통합 전에는 미확인을 대수에서 빼서 영상 A 는 N = 2, 영상 B 는 N = 1 이었습니다. 소대 구간 안이라 단계·S 는 같습니다 (`정리/부록/통합_전후_비교.md`).

## 5. Known / Known_Variant / Unknown 판정

계산 위치: `judge.py:36~62`, 임계값 `config.py:70~74`, 분류 점수 평균 `track.py:124~134`

**① 수식**
```
분류 점수(트랙) = 프레임별 top_k 점수를 탐지 신뢰도로 가중 평균
s1 = 1위 점수,  margin = s1 − 2위 점수
Known          : 1위가 사전에 있는 기종 그리고 s1 ≥ 0.6 그리고 margin ≥ 0.2
Known_Variant  : (Known 아님) 같은 계열 후보 점수 합 ≥ 0.6
Unknown        : 그 밖 (점수 합이 가장 큰 계열을 '추정 계열'로 기록)
```
**② 풀이**: 1위가 충분히 높고 2위와 확실히 차이 나야 기종을 믿습니다. 기종은 헷갈려도 후보들이 같은 계열이면 계열까지는 믿습니다.

**③ 대입**

| Tank-02 | TANK_0216 T-72 (0.410) | TANK_0220 T-72 (0.368) | 0.410 / 0.042 | T-72 = 0.778 | **Known_Variant** (T-72 계열) |
| UNK-001 | TANK_0231 T-90 (0.222) | TANK_0226 T-80 (0.190) | 0.222 / 0.032 | T-90 0.222, T-80 0.190 | **Unknown** (추정 T-90) |

## 6. 계열 상위 25%(p75)와 대체 규칙

계산 위치: `judge.py:65~78` `_group_p75`, `dictdb.py:59~69` `p75`·`family_stats`, 유형 p75 는 `sync_threat_db.py:81`

**① 수식**
```
p75(값 목록) = 작은 순으로 정렬했을 때 75% 위치의 값 (사이 값은 선형 보간)
              위치 = 0.75 × (개수 − 1)  → 정수 부분 칸과 다음 칸 사이를 소수 부분만큼
대체 순서: 계열 표본(계산 가능한 기종 수) ≥ 3 → 계열 p75
          아니면 → 유형 p75 (type_threat_summary) → 그것도 없으면 주력전차 p75
```
**② 풀이**: 모르는 전차를 그 무리의 '위험한 쪽' 값으로 봅니다. 평균(중앙값)을 쓰면 실제로 강한 개량형일 때 과소평가가 되기 때문입니다. 표본이 너무 적으면 p75 가 의미가 없어 더 큰 집단(유형)으로 넘어갑니다.

**③ 대입 — T-72 계열, 전술 10** (Tank-02)
```
T_10 값 6개 정렬: 74.3, 74.5, 79.5, 82.6, 86.6, 92.9
위치 = 0.75 × (6 − 1) = 3.75 → 4번째(82.6)와 5번째(86.6) 사이 0.75 지점
p75 = 82.6 + 0.75 × (86.6 − 82.6) = 85.6
```
**T-80 계열, 전술 1** (UNK-007): 83.3, 85.1, 86.1, 97.8, 102.2 → 위치 3.0 → **97.8**
**T-90 계열** (UNK-001): 사전에 2종(T-90, T-90M)뿐 → 2 < 3 → 유형 '주력전차' 전술 10 p75 = 88.93 → **88.9**, 근거 태그 "주력전차 상위25% (T-90 계열 표본 2 < 3)"

## 8. cope cage 보정

계산 위치: Known `judge.py:91~92`, 그 밖 `judge.py:103~105`, 배율 `config.py:79` (**TODO: 설문으로 확정 예정**)

**① 수식**
```
Known        : P' = P × 1.10 으로 바꿔 T 를 다시 계산
그 밖(p75 값) : ΔT = (w_P / 가중치 합) × P_p75 × (1.10 − 1),   T' = T + ΔT
               (계열 p75 를 못 쓰고 유형 값으로 대체했다면 P_p75 가 없어 보정하지 않고 태그만)
```
**② 풀이**: cope cage 는 위에서 오는 공격에만 일부 효과가 있어 방호력만 10% 올립니다. 미확인·변형은 T 가 이미 한 숫자로 합쳐져 있어서 P 몫만 떼어 더합니다.

**③ 대입**
```
Tank-02 (T-72 계열, 전술 10): ΔT = 0.37/0.99 × 83.7 × 0.10 = 3.13 → 85.6 + 3.1 = 88.7
UNK-007 (T-80 계열, 전술 1) : ΔT = 0.20/1.00 × 84.4 × 0.10 = 1.69 → 97.8 + 1.7 = 99.5
```
화면에는 둘 다 보여 줍니다: "99.5 위협도 · 보정 전 97.8".

## 9. 지휘전차 판정 (안테나 프레임 비율)

계산 위치: `track.py:104~108` `_flag`, 값 `config.py:57~62`

**① 수식**
```
n = 안테나가 신뢰도 0.5 이상으로 보인 프레임 수,  m = 그 트랙의 전체 프레임 수
```

## 10. 임베딩 유사도와 그룹 매칭

계산 위치: `track.py:137~145` (트랙 임베딩), `unknown_registry.py:82~96` (매칭), 값 `config.py:82~83`

**① 수식**
```
트랙 임베딩 e = normalize( 품질 상위 5프레임 임베딩의 평균 )        normalize = 길이를 1로
그룹 centroid c = normalize( 그룹 출현 기록 임베딩들의 평균 )
코사인 유사도 = e · c  (두 단위 벡터의 내적, -1 ~ 1)
유사도 ≥ 0.85 → 그 그룹 / 0.75 ~ 0.85 → 새 그룹 + 병합 후보 기록 / 0.75 미만 → 새 그룹
```
**② 풀이**: 임베딩(사진을 16개 숫자로 바꾼 것, 샘플 기준)의 방향이 비슷하면 같은 기종으로 봅니다. **'같은 개체'가 아니라 '같은 기종'** 추정입니다.

**③ 대입**: UNK-001(영상 A)이 첫 미확인 → 새 그룹 UNK-G0001. UNK-007(영상 B)과의 유사도 **0.9646** ≥ 0.85 → 같은 그룹. (참고: Tank-01 과 UNK-001 의 유사도는 -0.31 로 전혀 다름)
