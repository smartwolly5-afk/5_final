## 6. 모델 팀과의 계약에서 남은 질문 (`contract.md` 가정 표)

1. DINO 분류 라벨 단위: tank_id 인가, 계열인가? 실제 클래스 목록은? → `label_map.json`
2. 임베딩 차원과, 같은 기종 crop 끼리의 유사도 분포 → `GROUP_SIM_MIN` 보정
3. 트래커 종류, 추적이 끊기면 ID 를 다시 쓰는지
4. 부품을 전차 탐지 안에 넣어 주는지(`parts`), 프레임 단위로 따로 주는지
5. 원본 프레임 저장 위치 (지금은 Flask `static/` 아래만 읽음)
6. `cluster_id` 를 누가 붙이는지 (모델 / 전처리 / 우리 코드)
7. `captured_at` 형식

## 7. 향후 개선 아이디어

1. 확정·병합·기각 → 확정된 그룹은 Known 으로 자동 전환 (분석관 피드백이 시스템에 쌓이는 구조)
2. 군집 ID 를 위치(추정 좌표) 기반으로 자동 생성
3. 실시간 영상: 프레임 스트림을 일정 구간(예: 5초)마다 `/api/analyze` 로 보내는 방식 [팀 확인 필요 — 처리 속도 측정 전]
4. 대시보드 상태를 DB(`cluster_assessment`)에 저장해 서버 재시작·다중 사용자 대응
5. 두 대응수준 엔진 통합 (v2 판정 → `response_level.assess` 어댑터)
6. 전술 가중치를 DB 한 곳에서만 읽기
7. 임계값 자동 보정 스크립트 (검증셋 → 유사도 분포 → 추천 임계값)
